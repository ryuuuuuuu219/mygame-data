# M01 地上敵配置

## 優先度

1

## 目的

M01 の敵配置を、航空機中心から地形に沿った地上敵中心へ切り替える。

空戦だけでなく、地形・対地攻撃・防空網を含むミッションとして成立させる。

## タスク

### 1-0. 事前整理：スポーン・目標フラグ・地上敵コンポーネント

1-1 以降のプレハブ化に入る前に、M01 の敵配置をデータで安定管理できるようにする。

- スポーンシステムの現状を把握する。
  - `SpawnTableManager`、`stage_spawns.json`、`AugumentStatus.missionObjective`、`ObjectManager.NotifyEnemyDestroyed` のつながりを確認する。
  - 現状の `isMissionTarget` は `enemyIds` と同順の bool 配列なので、敵数が増える M01 では指定漏れ・順番ずれが起きやすい。
- JSON ファイルのミッション目標フラグ方式を見直す。
  - 目標候補は、敵 ID 指定・目標 ID リスト・敵定義ごとのフラグなど、後から読んで間違いにくい形式へ寄せる。
  - M01 で「破壊必須の地上目標」と「脅威だが必須ではない防空戦力」を分けられるようにする。
- 機銃発射・ミサイル発射のコンポーネントを制作する。
  - `Assets/script/mission/enemy/GraundTGT.cs` の処理を流用する。
  - ただし、AA_GUN と SAM の再利用性を上げるため、ターゲット探索、機銃発射、ミサイル発射、ロック条件を分離できるか確認する。
  - 実装済み: `EnemyTargetSelector`、`EnemyGunShooter`、`EnemyMissileShooter`、`GroundAntiAirController` に分割。
- スポーンシステムと座標指定を整備する。
  - M01 の AA は一定高度以上、かつ地形コライダー上に配置する。
  - M01 の SAM は谷底に配置する。
  - 乱数の種を固定し、配置のばらつきと対空陣地の場所を再現可能にする。

#### 事前評価

この順番は妥当。理由は、先に AA_GUN/SAM プレハブを作ってからスポーン JSON や座標方式を変えると、プレハブ側の検証条件が後から揺れるため。
特に M01 は敵数が多く、現状の `isMissionTarget` bool 配列は `enemyIds` の順番に強く依存するので、地上敵化の前にミッション目標指定を読みやすくしておく価値が高い。

### 1-1. 対空機銃（AA_GUN）のプレハブ化

- 地上配置できる対空機銃プレハブを作る。
- 地形上に置いても向き・射界・当たり判定が破綻しないようにする。
- M01 で配置テストできる状態にする。
- 実装済み: `Assets/prefub/enemy/AA_GUN.prefab` を追加。

### 1-2. 対空ミサイル（SAM）のプレハブ化

- 地上配置できる対空ミサイルプレハブを作る。
- ロック、発射、誘導、弾切れまたはクールタイムを確認できる状態にする。
- M01 で配置テストできる状態にする。
- 実装済み: `Assets/prefub/enemy/SAM.prefab` を新コンポーネント構成へ更新。

### 1-3. 対空ミサイルを防空網として強化

- 対象高度に応じて射程が伸びるようにする。
- 高高度侵入と低高度侵入でリスクが変わるようにする。
- 単体 SAM ではなく、防空網としてステージに圧を作る。

## 完了条件

- M01 に地形に沿った地上敵を配置できる。
- 航空機敵の一部または全部を地上敵へ置き換えられる。
- AA_GUN と SAM がプレハブとして再利用できる。
- 高度によって SAM の脅威範囲に差が出る。
