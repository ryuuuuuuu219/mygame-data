# 敵機銃の照準・偏差射撃・バイアス仕様

## 前提

弾体には、発射後に直線的に飛翔する C# スクリプトがある。

そのため、発射側の責務は「弾をどう動かすか」ではなく、「発射時点でどの方向・どの速度ベクトルを与えるか」を決めることに集約される。

敵機銃側では、最終的に次のような発射ベクトルを作る。

```text
発射ベクトル = 発射母体の速度 + 射線方向 * 弾速
```

ここで重要なのは、敵の照準処理が最終的にひとつの `Vector3`、つまり三次元の発射方向ベクトルを決める処理だという点である。

本仕様では、その発射方向を次の三段階で作る。

1. 直接照準
2. 偏差射撃
3. バイアス

## 第一段階: 直接照準

もっとも単純な照準は、敵の銃口または敵本体から目標の現在位置へ向かう方向である。スクリプト上は、射撃処理に渡された方向ベクトルを正規化し、目標情報がない場合の発射方向として使う。

これは、目標座標と銃口座標の差分を取り、その座標差ベクトルを正規化することで求められる。

```text
座標差ベクトル = 目標の現在座標 - 銃口座標
直接照準方向 = 座標差ベクトルを正規化したもの
```

この段階では、目標が移動していることは考慮しない。静止目標や、弾速が十分に速く移動量を無視できる場合には、この直接照準だけでも成立する。

一方で、目標が高速に移動している場合、現在位置を狙って撃つと、弾が到達する頃には目標がそこから移動している。そのため、直接照準は偏差射撃の基礎ではあるが、移動目標に対しては次の段階で補正する。

## 第二段階: 偏差射撃

偏差射撃では、目標の現在位置へ向かう直接照準ではなく、弾が届く頃に目標がいると予測される位置へ発射方向を置き換える。スクリプト上は、目標 Transform と目標速度が渡された場合に、直接照準方向ではなく偏差射撃で求めた方向を使う。

考え方としては、「弾の飛翔距離」と「目標までの距離」を時間の関数として扱い、両者が一致する交点を求める。

弾は一定速度で直線的に飛ぶため、発射から `t` 秒後の飛翔距離は次のように表せる。

```text
弾の飛翔距離 = 弾速 * t
```

これは時間 `t` に比例するため、一次関数として扱える。

一方、目標も速度を持って移動しているため、`t` 秒後の目標位置は次のように表せる。

```text
t秒後の目標位置 = 目標の現在座標 + 相対速度 * t
```

ここで扱っている位置と速度は、すべて三次元座標・三次元ベクトルである。

銃口から見た目標の現在位置を「目標までの差分ベクトル」とすると、`t` 秒後の目標までの差分ベクトルは次のようになる。

```text
t秒後の目標までの差分ベクトル = 目標までの差分ベクトル + 相対速度 * t
```

このベクトルの長さが、同じ `t` 秒間で弾が飛べる距離と一致する時刻を求める。

```text
|目標までの差分ベクトル + 相対速度 * t| = 弾速 * t
```

このままだと左辺がベクトルの長さなので、両辺を二乗して距離の二乗として比較する。

```text
|目標までの差分ベクトル + 相対速度 * t|^2 = (弾速 * t)^2
```

設計上の発想としては、中学数学の三平方の定理で考えればよい。三次元座標では、距離の二乗は x方向、y方向、z方向それぞれの差分を二乗して足したものになる。

```text
距離の二乗 = x方向の差分^2 + y方向の差分^2 + z方向の差分^2
```

各方向の差分には「現在の差分 + 相対速度 * t」が入るため、それぞれを二乗して足し合わせると、`t^2` の項、`t` の項、定数項を持つ二次式になる。

```text
(x方向の差分 + x方向の相対速度 * t)^2
+ (y方向の差分 + y方向の相対速度 * t)^2
+ (z方向の差分 + z方向の相対速度 * t)^2
= (弾速 * t)^2
```

実装上は、これと同じ計算を三次元ベクトルの内積としてまとめて書いている。三平方の定理で各軸を展開した結果を、ベクトル計算として短く表したものが内積である。

```text
(相対速度・相対速度 - 弾速^2) * t^2
+ 2 * (目標までの差分ベクトル・相対速度) * t
+ (目標までの差分ベクトル・目標までの差分ベクトル)
= 0
```

スクリプト上では、この二次方程式の係数を次のように作っている。

```text
a = 相対速度・相対速度 - 弾速^2
b = 2 * 目標までの差分ベクトル・相対速度
c = 目標までの差分ベクトル・目標までの差分ベクトル
```

このとき、二次方程式は次の形になる。

```text
a * t^2 + b * t + c = 0
```

会合時刻 `t` は、解の公式で求める。

```text
t = (-b ± √(b^2 - 4ac)) / 2a
```

平方根の中身 `b^2 - 4ac` が 0 以上であれば、交点候補となる時刻を計算できる。候補が複数ある場合は、0 より大きい解のうち、もっとも小さい値を採用する。これは「弾が最初に目標へ届く時刻」を選ぶためである。

つまり、弾の飛翔距離は一次関数だが、目標までの距離は三平方の定理で各軸の二乗和として扱うため、距離の二乗に展開すると二次関数になる。実装では、この二次方程式に対して機械的に解の公式を使い、弾と目標が交差しうる時刻を導出している。正の解が複数ある場合は、最も早く到達できる時刻を採用する。

交点時刻が求まったら、その時刻における目標位置を会合点とする。

```text
会合点 = 目標の現在座標 + 相対速度 * 会合時刻
偏差射撃方向 = 銃口から会合点へ向かう方向
```

これにより、敵は目標の現在位置ではなく、未来位置を先読みして撃つ。

## 第三段階: バイアス

偏差射撃だけでは、敵が正確に未来位置を撃ち抜き続けるため、挙動が機械的で強すぎるものになりやすい。

そこで第三段階として、第二段階で求めた会合点を中心に、射線を意図的に揺らすバイアス処理を加える。

このバイアスは、単純な命中率低下ではなく、「目標の未来位置を中心に、その周辺を薙ぎ払うように射線を動かす」ための処理である。

イメージとしては、偏差射撃で求めた会合点を中心に小さな円を置き、その円内または円周方向へ照準をずらす。敵の射線は、そのずらされた照準へ向かうため、会合点を中心とした周辺空間をなめるように動く。

```text
基準点 = 偏差射撃で求めた会合点
バイアス後の照準 = 基準点の周辺に置かれた揺らぎ点
バイアス後の射線方向 = 銃口からバイアス後の照準へ向かう方向
```

実装上は、会合点そのものを直接ランダム移動させるというより、偏差射撃方向に対して左右・上下の角度差を加える形で処理している。結果として、会合点を中心とした円内で射線が揺れる挙動になる。

このバイアス角は毎発完全にランダムに変わるのではなく、現在のズレ角が次の目標ズレ角へ徐々に近づいていく。これにより、射線は細かく瞬間移動するのではなく、会合点の周辺を滑らかに薙ぎ払う。

バイアスには次の役割がある。

- 偏差射撃の正確さを保ったまま、必中感を下げる。
- 目標の未来位置周辺に弾を流し、回避行動の余地を作る。
- 敵の射撃に、照準補正や制圧射撃らしい動きを与える。
- 複数銃身の場合、銃身ごとに異なる揺らぎを持たせる。

## 追加要素: 銃身配置と散布

三段階の照準処理に加えて、武器の見た目や弾幕密度を調整するための要素がある。

複数銃身を持つ機銃では、銃身ごとに発射方向を扇形へ分けられる。これは照準の誤差ではなく、武器そのものの発射レイアウトである。銃身数と扇形角度を大きくすると、一点集中ではなく面を覆う弾幕になる。

また、発射ごとに小さなランダム散布を加えられる。これはバイアスとは異なり、一発ごとに独立した瞬間的なばらつきである。

- バイアス: 会合点周辺を滑らかに薙ぎ払う継続的な射線の揺れ。
- ランダム散布: 各弾に加える瞬間的な誤差。
- 銃身配置: 複数銃身による武器形状としての広がり。

## 調整項目

| 日本語名 | 実装上の名前 | 役割 |
| --- | --- | --- |
| 銃身数 | `barrelCount` | 一度に発射する銃身の数。 |
| 銃身扇形角度 | `barrelArcAngle` | 複数銃身をどれだけ横方向へ広げるか。 |
| 弾速 | `bulletSpeed` | 弾そのものの速度。偏差射撃の交点導出にも使う。 |
| 発射間隔 | `fireRate` | 次弾を撃てるようになるまでの時間。 |
| ランダム散布角 | `spreadAngle` | 一発ごとの瞬間的なばらつき角度。 |
| バイアス使用 | `useLeadBias` | 会合点周辺を薙ぎ払う射線揺れを使うか。 |
| バイアス移動速度 | `biasDegreeSpeed` | 現在のズレ角が目標ズレ角へ近づく速さ。 |
| バイアス量 | `biasDegree` | 会合点周辺からどれだけ射線を外すかの角度幅。 |
| 再抽選の最低角度差 | `rerollAngleThreshold` | 次のズレ方向を選ぶ際、前回方向から最低どれだけ離すか。 |
| 中央復帰判定幅 | `centerSnapThreshold` | 反対方向付近を選んだとき、中央へ戻す判定幅。 |
| 射線確認 | `requireLineOfSight` | 地形などに遮られている場合に射撃を止めるか。 |

## 調整例

精密な敵にしたい場合は、バイアスを無効にし、ランダム散布角を小さくする。目標の未来位置を正確に狙うため、直線的に飛ぶ目標には強くなる。

未来位置は読むが回避余地のある敵にしたい場合は、バイアスを有効にし、バイアス量を小さめにする。バイアス移動速度を低めにすると、射線が会合点周辺をゆっくり薙ぎ払う。

弾幕として面を制圧したい場合は、銃身数を増やし、銃身扇形角度を広げる。さらにランダム散布角を少し加えると、規則的すぎない弾幕になる。

毎発ごとに大きく散らしたい場合は、ランダム散布角を増やす。バイアスは継続的な射線揺れなので、瞬間的な散り方を作る用途ではランダム散布角の方が直接効く。

## 実装上の対応

主な実装は、敵機銃の発射ベクトルを作る処理と、バイアスを管理する追加処理に分かれている。

- 敵機銃の射撃処理: `Assets/script/mission/Enemy/Weapons/EnemyGunShooter.cs`
- バイアス処理: `Assets/script/mission/Enemy/Weapons/EnemyGunLeadBiasAddon.cs`
- 対空砲からの呼び出し: `Assets/script/mission/Enemy/Weapons/GroundAntiAirController.cs`
- 旧方式の参考実装: `Assets/script/mission/Enemy/Weapons/FCS_e.cs`

内部的には、まず直接照準方向を作り、目標情報がある場合は偏差射撃方向へ置き換える。その後、バイアス、銃身ごとの扇形配置、ランダム散布の順で方向を補正し、最後に弾速と発射母体速度から弾の発射ベクトルを決定する。

## 注意点

- 偏差射撃は、目標速度が正しく取得できることを前提にしている。
- 弾速が極端に低い場合、交点導出や実際の射撃挙動が不自然になりやすい。
- バイアスは、射撃処理が呼ばれている間だけ進む。射程外などで射撃処理が呼ばれない間は、揺れ状態も進まない。
- 射線確認が有効な場合、地形などで遮られている目標には発射しない。
- デバッグ用の照準線表示機能は用意されているが、現状では通常の射撃処理からは呼び出されていない。
