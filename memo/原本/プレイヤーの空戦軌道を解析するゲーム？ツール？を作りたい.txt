◇EnemyAircraftAIGen4 整理メモ：実装保留

目的：
プレイヤー挙動解析ツールと、将来の成長AI実装を妨げる要素を取り除く。
ただし今回はコード編集を保留し、次に行うべき修正方針として整理する。

前提：
・CombatState.Pursuitおよびピュア追尾は削除済みとして扱う。
・targetRbは維持する。
・プレイヤーのpitch / roll / yaw / throttle入力を敵AIへ直接渡さない。
・今回は機械学習、成長AI、解析機能そのものは追加しない。
・完全なランダム性ゼロよりも、行動理由を追跡・説明できる構造を優先する。

目標：
・AIの行動理由を追跡可能にする。
・同一状況に対する挙動を再現可能にする。
・無関係な乱数による状態変化を除去する。
・解析ツールが算出した特徴量を将来利用できる構造へ近づける。
・プレイヤー入力の直接模倣ではなく、状況判断と行動選択の傾向を模倣できるようにする。

優先して削除・修正するもの：

1. 攻防認識のランダム反転を削除する
・invertOffensiveTactic
・tacticSwitchCheckInterval
・tacticSwitchChance
・tacticSwitchCooldown
・nextTacticSwitchCheckTime
・nextTacticSwitchTime
・UpdateOffensiveTactic()
・invertOffensiveTactic による offensive の反転処理

暫定的には以下のようにする。

```csharp
bool offensive = baseOffensive;
```

攻撃側・防御側という状況認識そのものを乱数で反転しない。
戦術の多様性は、同じ攻撃状況または防御状況の中で行動候補を変える形で将来実装する。

2. ランダムな強制状態遷移を削除する
・randomManeuverCheckInterval
・randomManeuverChance
・randomManeuverCooldown
・nextRandomManeuverCheckTime
・nextRandomManeuverTime
・TryPickRandomManeuver()
・TryPickRandomManeuver() の呼び出し
・TryPickRandomManeuver() からのみ使われている場合の ForceState()

無関係な乱数で AoALimitRelease / LeadPursuit / Brake / Extend / Offset へ強制遷移させない。
ミサイル回避も、ランダムチェック成功時だけ回避する構造にしない。

3. remainTimeによる不透明な重み生成を削除する
削除または置換対象：
・needToChoiceTime
・maxTime
・remainTime
・weight
・UpdateStateChoiceTimes()
・GetStateWeight()
・ResetStateRemainTime()

現在のremainTimeは、条件未成立中にも蓄積し、条件成立時に過去の蓄積が選択重みになるため、行動理由が追跡しづらい。
状態候補は現在フレーム、または短時間継続した conditionMet から決定する。
乱数抽選は使わない。

候補案：
・conditionMet が true の状態を、明示的な固定優先順位で選ぶ。
・または deterministicScore を与え、最大スコアの状態を選ぶ。

4. 毎フレームの重み付きランダム抽選を削除する
・TryGetStateCandidate()
・Random.value を使った重み付き状態抽選

同じ conditionMet の組み合わせなら、同じ状態候補が選ばれるようにする。

暫定優先順位：
1. 高度安全処理
2. ミサイル回避
3. Brake
4. Extend
5. AoALimitRelease
6. LeadPursuit
7. Offset
8. 現在状態維持

5. AoALimitRelease中のpitch補正式を連続値に修正する
現在の式は演算子優先順位により、ほぼ0または1の二値になる。
以下のようにローカル変数へ分ける。

```csharp
float pitchAvailability =
    Mathf.Clamp01(
        1f
        - pitchAxisError * 1.6f
        - downFactor);

pitch *= pitchAvailability;
```

6. TuningOverwriteによるランダム初期化を削除する
・enterDelayRandomAddMax
・minimumDurationRandomAddMax
・TuningOverwrite()
・Awake内のTuningOverwrite呼び出し

Inspectorに設定された enterDelay と minimumDuration をそのまま使用する。
個体差は将来的にパイロット設定、またはScriptableObjectから明示的に与える。

7. 攻撃優位判定を専用メソッドへ切り出す
ChooseState内に直接埋め込まず、以下のようなメソッドに分離する。

```csharp
bool EvaluateOffensiveState(
    float ownNoseToTargetAngle,
    float targetNoseToOwnAngle)
{
    return targetNoseToOwnAngle > ownNoseToTargetAngle;
}
```

将来はこの責務を、解析ツールが算出する以下の特徴量へ置き換える。
・AdvantageScore
・ThreatScore
・ClosureRate
・LongitudinalPosition
・GunSolutionError

8. 戦術選択と機体制御指示を分離する方向へ寄せる
今回CombatState enumを全面置換する必要はない。
ただし、以下の処理を「現在状態から操縦計画を生成する」構造へ寄せる。
・GetLimiter()
・GetThrottleInput()
・BuildTargetDirection()
・SteerToward()

将来の目標：

```text
状況認識
→ 戦術選択
→ 操縦計画
→ AircraftControllerへの入力
```

操縦計画の案：

```csharp
struct ControlPlan
{
    public Vector3 targetDirection;
    public float throttle;
    public bool limiterOn;
    public bool useMissileBarrelRoll;
}
```

9. GetOffsetVectorのランダム方向選択を削除する
削除対象：
・Random.value による左右反転
・Random.Range によるvertical選択

暫定ルール：
・左右方向は現在の機体右方向に近いsideを選ぶ。
・verticalは固定値0にする。

```csharp
if (Vector3.Dot(side, transform.right) < 0f)
    side = -side;

float vertical = 0f;
```

将来は解析済み特徴量から選択する。
・左右旋回傾向
・上下回避傾向
・敵の旋回方向
・高度余裕
・過去の成功率

10. 緊急処理と通常戦術を分離する
緊急処理：
・RecoverAltitude
・EvadeMissile

通常戦術：
・Brake
・Extend
・AoALimitRelease
・LeadPursuit
・Offset

ChooseStateでは、先に緊急状態を評価し、その後に通常戦術を評価する。
緊急状態を通常戦術と同じランダム抽選候補に入れない。

11. 状態遷移予約を安定させる
bookedStateは維持する。
ただし候補状態が毎フレーム乱数で変化する問題をなくす。

保証したいこと：
・決定論的なChooseState結果がbookedStateへ入る。
・候補が変わった場合のみbookedStateTimerをリセットする。
・同じ候補が続く間はbookedStateTimerが増える。
・enterDelay到達後に遷移する。
・currentStateのminimumDuration中は、緊急状態を除いて通常遷移しない。
・高度危険やミサイル危険は、必要に応じてminimumDurationを無視できる。

緊急割り込み条件は専用メソッドへ分離する。

```csharp
bool CanInterruptCurrentState(CombatState requestedState)
```

12. ランダム性を残す場所を限定する
残してよい候補：
・ミサイル回避時のバレルロール方向
・同価値の左右回避候補から選ぶ処理

ただし乱数によって以下が起きてはいけない。
・攻撃と防御の認識が反転する。
・危険状態を無視する。
・全く異なる戦術へ強制遷移する。

可能なら、使用した乱数結果をデバッグ表示する。

targetRbとプレイヤー模倣の制約：
・targetRbは維持する。
・敵AIはプレイヤーの生の操作入力を直接使用しない。

禁止：
・playerPitchInput → enemyPitchInput
・playerRollInput → enemyRollInput
・playerYawInput → enemyYawInput
・playerThrottleInput → enemyThrottleInput

将来使うものは解析済み特徴量に限定する。
・旋回開始遅延
・左右旋回傾向
・平均接近率
・Brake選択頻度
・Extend選択頻度
・リミッター解除頻度
・追尾誤差
・オーバーシュート頻度

変更前の状態選択フロー：
1. ターゲットとミサイル脅威を更新する。
2. remainTimeとweightを更新する。
3. 攻防認識を乱数で反転する場合がある。
4. ランダム強制遷移が発生する場合がある。
5. StateRuntimeのweightからランダム抽選で候補状態を選ぶ。
6. bookedStateとenterDelayで遷移を確定する。

変更後に目指す状態選択フロー：
1. ターゲットとミサイル脅威を更新する。
2. 現在フレームの状況から conditionMet を更新する。
3. 高度危険・ミサイル危険などの緊急状態を決定論的に評価する。
4. 緊急状態がなければ、通常戦術を固定優先順位またはdeterministicScoreで選ぶ。
5. 決定論的な候補状態をbookedStateへ渡す。
6. bookedStateが一定時間継続したらenterDelay後に遷移する。
7. 操縦計画を生成し、AircraftControllerへ入力する。

完了条件メモ：
・Unityでコンパイルエラーがない。
・攻防認識を乱数で反転する処理がない。
・無関係なランダム強制状態遷移がない。
・remainTimeによる不透明な重み付き抽選がない。
・同一条件から同一状態候補が選ばれる。
・AoALimitReleaseのpitch補正が連続値として動作する。
・Inspector値へランダム加算する処理がない。
・Offset方向が決定論的である。
・緊急処理と通常戦術が分離されている。
・targetRbが維持されている。
・プレイヤー入力を敵AIへ直接接続していない。
